# zEngine 强化路线图（zMmoServer 能力下沉）

> **这份文档是什么**：zMmoServer 在真实 realm MMO 压力下，把一批 **game-agnostic 的分布式/并发承重件**
> 在应用层（zCommon）实现了出来——它们本该是引擎能力。本路线图记录「把它们回归 zEngine」的工作：
> 已落地的、以及按收益排序的后续项。
>
> **一条铁律**：下沉不得引入反向依赖（引擎零 import 应用层）；只沉机制，业务枚举/胶水留在应用；每项挂测试。
>
> **规范边界**：下沉前必须逐项对照 [层次边界与演进原则.md](层次边界与演进原则.md)。
>
> **版本**：0.0.23 ｜ **创建**：2026-07-27 ｜ **更新**：2026-09-04。
>
> **口径**：表中的“已落地”表示代码和部分测试已经进入 zEngine，不等于上层生产路径已全部采用，
> 也不等于失败恢复、资源关闭和业务事务已经闭环。“后续路线图”描述目标顺序，不是当前能力清单。

## 三、后续路线图：先加固承重件，再继续下沉

1. **OWN-01 已完成，下一层工作回到应用状态机**：OwnershipStore 已由四角色服务实例注册真实承重，
   证明 owner/lease/epoch、旧写拒绝和 watch 恢复；zEngine 不继续吸收 `service-instance`、活动分配或迁移
   状态。下一步按 zMmoServer 执行计划推进 ALLOC/DRN/MIG，并只在出现第二个真实通用需求时扩引擎 API。
2. **NET/ACT/AOI/HLT/LIF**：NET-01/02/03 已完成 TCP/UDP/WS 分配前帧校验、端点级 byte order、
   解密/解压后上限、分类指标、有界发送、worker admission、router 生命周期和三种投递等级；网络下一步
   是 `VER-01` 版本协商。ACT-01/02 已分别完成 Runner 严格单写者和 BaseActor admission/监督契约；
   AOI-01 的代码、E1/E2 和真实移动 E4 均已完成，HLT-01/LIF-01 也已完成。生命周期继续由
   zServer/zService 分层承担，不新增第三套框架；业务排空仍由后续 DRN-01 承担。
3. **discovery 拆层**：只把 Registry/Lease/Watch、revision、context 和断线恢复机制放入 zEngine；
   `ServerInfo.GroupID/MapIDs/Players`、六位 ServerID 编码和服务角色筛选留在 zCommon 适配层。
4. **connpool + NetPacket 池归位 `zNet`**：客户端连接池 + `NetPacket` 对象池本就是 zNet 该有的；
   但仍须先证明真实调用和池化收益，不能仅因目录归属“看起来正确”直接搬。
5. **parallel（分区 tick 调度器）**：纯净，但当前 0 接线——下沉前先在应用真正接一次验证。
6. **仅评估通用 correlation frame**：当前 Envelope 含 `SourceServerID/SourceService`，外层 codec 又含
   PlayerID/MapID 和 Game/Map 路由，整体留在 zCommon。至少两个真实协议复用时，才新增不含业务字段的
   version/trace/request/timestamp/message-kind 机制；不直接搬现有 40B Envelope。
7. **ID 机制拆层**：在真实调用证明需求后评估 `Snowflake` 和 `TypedID[Tag]` 基座；六位 ServerID 的
   `GroupID+ServerIndex` 编码和 20+ 业务 ID tag 留在 zMmoServer。
8. **lifecycle 只强化 `zServer`/`zService`**：zServer 已负责启动事务、context 和幂等 Stop；zService
   负责可选 DAG、回滚和错误聚合。只用 Gateway report 做一条生产接线，没有一次性重写四进程。

**不下沉**（纯业务）：`cache`、`game`、crossserver 的 MMO 语义部分、serverconnmgr（太薄，zNet 已覆盖）。

## 四、下沉原则（沉淀）

- **单向依赖**：引擎零 import 应用（`grep` 已验证 zEngine 不 import zCommon/zMmoServer）。下沉前先查目标包是否 import 了 zCommon——若有则先解耦。
- **只沉机制，留业务**：把业务枚举、语义包装、接线胶水留在应用，只把 game-agnostic 的机制搬进引擎。
- **先验证再下沉**：0 接线（建了没用）的组件，下沉前先在应用真正接一次、跑通，避免把未验证代码固化进引擎。
- **每项挂测试**：下沉后在引擎侧补/迁测试；替换应用自造件需完整回归 + 并发 `-race`。
- **兼容优先**：公共 API 按“新增兼容 API → 迁移真实调用者 → 搜索零调用 → 单独删除旧 API”推进。
- **先守现状**：替换底层机制前先补 characterization/E2E，保护 realm、权威分层、MAP-2 和 AOI
  单一权威；不以大规模重命名、拆服务或造接口作为成果。
